# «АтомПросвет» — Техническое задание (Этап 1)

Образовательный веб-тренажёр-симулятор пульта управления атомной электростанцией
для школьников и студентов. Демонстрационный проект для конкурса стартап-проектов
«Startup Energy», с привязкой к белорусскому контексту (БелАЭС, энергобаланс страны).

## 1. Технологии

- React 18 + TypeScript + Vite
- Tailwind CSS для стилей
- SVG для приборных шкал/индикаторов, Recharts для графика истории показателей
- Состояние: Zustand (глобальный игровой стор) + локальный React state там, где достаточно
- Framer Motion — микро-анимации и переходы (подключается на этапе полировки)
- Полностью клиентское приложение: без backend, без базы данных, без сети

## 2. Экраны и пользовательские сценарии

### 2.1 Стартовый экран (`StartScreen`)
Логотип «АтомПросвет», анимация запуска станции, кнопка «Начать смену» и (на
финальном этапе) кнопка «Демо-сценарий». Короткий онбординг из 2-3 карточек:
кто ты (оператор смены), что нужно делать, где искать справку.

**Сценарий:** пользователь открывает приложение → видит заставку → нажимает
«Начать смену» → попадает на пульт управления.

### 2.2 Пульт управления (`Dashboard`) — главный экран
Центральный экран игры, активен всё игровое время.

Содержит:
- круговые/дуговые индикаторы: мощность реактора, температура, давление,
  уровень безопасности (цвет: зелёный/жёлтый/красный + пульсация в опасной зоне);
- элемент управления мощностью (слайдер или кнопки +/-, ступенчато, без
  мгновенных скачков — реализуется в движке через плавное приближение к целевому
  значению);
- график истории показателей за последние 60 секунд;
- индикатор выработки энергии и ползунок/переключатель распределения
  «город / промышленность»;
- панель тревог — всплывающие уведомления о нештатных событиях + журнал
  последних 10 событий с результатом реакции;
- иконка вызова панели «Справка» и переход на экран «Факты».

**Сценарий:** пользователь регулирует мощность и распределение энергии,
следит за индикаторами, реагирует на всплывающие события (например, выбирает
действие «включить резервный насос»), избегая ситуаций, когда безопасность
падает до нуля.

### 2.3 Панель «Справка» (`HelpPanel`, боковая выезжающая панель)
Объясняет простым языком, за что отвечает каждый параметр и почему он важен
для реальной АЭС. Открывается по кнопке; при наведении/нажатии на любой
индикатор дополнительно показывается короткий tooltip (1-2 предложения).

### 2.4 «Факты об атомной энергетике» (`FactsScreen`)
Отдельный экран с 6-8 карточками: как работает реактор, как обеспечивается
безопасность, доля АЭС в энергобалансе Беларуси, сравнение выбросов CO2
атомной и тепловой генерации, факты о БелАЭС. Доступен из пульта, не прерывает
игру (можно открыть и закрыть, игровое время продолжает идти или ставится на
паузу — уточняется на этапе реализации).

### 2.5 Экран итогов смены (`SummaryScreen`)
Показывается по истечении игрового времени (по умолчанию 5 минут) или по
кнопке «Завершить смену»: набранные баллы, разблокированные достижения,
краткая сводка (сколько событий отработано, средняя безопасность, эффективность
распределения энергии), итоговое звание («Стажёр» / «Оператор» / «Главный
инженер смены»), кнопка «Начать заново».

## 4. Упрощённая физическая модель реактора

Модель условная, без реальных ядерных расчётов, но внутренне логически
согласованная и детерминированная (одинаковый вход → одинаковый выход).

### 4.1 Параметры состояния

| Параметр | Диапазон | Описание |
|---|---|---|
| `power` | 0–100% | Текущая мощность реактора |
| `targetPower` | 0–100% | Целевая мощность, задаётся пользователем |
| `temperature` | 200–500 усл. °C | Температура активной зоны |
| `pressure` | 0–20 усл. МПа | Давление в контуре |
| `coolantFlow` | 0–100% | Эффективность охлаждения (падает при отказе насоса) |
| `safety` | 0–100% | Интегральный уровень безопасности |
| `energyOutput` | МВт | Текущая выработка энергии |
| `cityShare` / `industryShare` | 0–100%, сумма = 100 | Распределение энергии |
| `gridDemand` | МВт | Текущий спрос сети (меняется во времени, задаёт нагрузку) |

### 4.2 Правила одного тика симуляции (`tick`)

1. **Мощность** плавно приближается к `targetPower` с ограниченной скоростью
   (например, не более ±3%/сек) — это и есть «защита от резких действий»
   из этапа 8.
2. **Равновесная температура** — функция от мощности и `coolantFlow`:
   выше мощность → выше равновесная температура; выше `coolantFlow` → ниже
   равновесная температура. Фактическая температура каждый тик сдвигается к
   равновесной с некоторой инерцией (а не скачком).
3. **Давление** пропорционально температуре с небольшим шумом (случайные
   колебания в узком диапазоне для «живости» показаний).
4. **Уровень безопасности** снижается, когда температура/давление выходят
   за пороги «норма», и восстанавливается медленно, когда параметры в норме.
   При `safety = 0` — авария, смена завершается досрочно с худшим итогом.
5. **Выработка энергии** = функция от `power` (мощность → МВт) с потерями
   при `coolantFlow` ниже нормы. Делится между городом/промышленностью по
   `cityShare`/`industryShare`; несоответствие выработки и `gridDemand`
   штрафует «эффективность» в итоговой оценке.
6. **Активные события** временно модифицируют параметры (правило 2-5) —
   например, «отказ насоса охлаждения» снижает `coolantFlow` на время события
   или до выбора пользователем корректирующего действия.

### 4.3 Пороговые значения (индикация)

| Параметр | Зелёный (норма) | Жёлтый (предупреждение) | Красный (опасность) |
|---|---|---|---|
| Температура | 250–350 | 350–400 | > 400 (авария при > 450) |
| Давление | 6–12 | 12–15 / 4–6 | > 15 или < 4 |
| Безопасность | 70–100 | 40–70 | < 40 (авария при 0) |

### 4.4 Нештатные события (каталог для этапа 5)

- Скачок нагрузки в сети — резко растёт `gridDemand`.
- Плановое техобслуживание блока — временное ограничение `targetPower`.
- Отказ насоса охлаждения — падение `coolantFlow`, требует действия
  пользователя («включить резервный насос») в ограниченное время.
- Экстремальная погода — колебания `gridDemand` в течение периода.

Каждое событие: заголовок, описание, эффект на параметры, тайм-лимит на
реакцию, результат (справился/не справился) — пишется в журнал событий и
влияет на очки (этап 6).
